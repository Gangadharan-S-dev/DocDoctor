# DocDoctor Security Notes

Last audited: Phase 5. Scope: browser app (`src/`) + conversion service (`server/`).

## Model

73 of 75 tools process files **entirely in the browser** — uploaded files never
leave the device, so there is no server-side file storage to breach for them.
The 2 LibreOffice-backed tools upload to the optional conversion service over
the deployment's own origin.

## Controls verified in code

| Area | Control |
|---|---|
| XSS | No `dangerouslySetInnerHTML`, `eval`, or `document.write` anywhere in `src/`. All user text renders through React escaping; JSON/XML results preview inside `<pre>`. Downloaded HTML (Word→HTML, Excel→HTML) is generated by mammoth/SheetJS, which escape document text. |
| Zip extraction | Entry names sanitized (`../` stripped — see `safeName` in `src/processing/text.ts`); max 200 entries; declared-uncompressed guards: 200 MB/entry, 500 MB total (zip-bomb). Covered by tests in `tests/office.test.mjs`. |
| Upload validation | Extension + size limits per tool in the shared UploadArea; engines then parse real content and fail with honest errors (no extension-only trust — a renamed file simply errors in its parser). |
| PDF/Office parsers | pdf-lib, PDF.js, JSZip, SheetJS, mammoth run in the page sandbox; malicious documents can at worst crash the tab (ErrorBoundary shows a recovery screen; nothing persists). |
| Object URLs | Preview/download URLs are revoked (`src/processing/download.ts`, ToolPage effects). |
| Macros/scripts | Never executed: Office files are parsed as data only. |
| External requests | The app itself makes no third-party calls; the only external fetch is Google Fonts (fonts.googleapis.com / fonts.gstatic.com). Self-host the two font families if even that is unacceptable. |
| Conversion service | Isolated per-job temp dirs under the OS temp folder; files deleted in a `finally` after every request plus a 30-minute sweeper; 50 MB upload cap; 30 conversions/10 min/IP rate limit; 120 s converter timeout; job IDs are UUIDs; errors return messages only — never paths or stack traces; LibreOffice spawned with an argv array (no shell, so filenames cannot inject commands; filenames are also sanitized). |
| Deployment headers | CSP, `nosniff`, frame denial, referrer and permissions policies shipped in `vercel.json` and `public/_headers`. |

## Known limits

- Browser tools hold files in tab memory; very large files near the per-tool
  caps can pressure low-memory devices. Caps are stated on every tool page.
- The conversion server binds `127.0.0.1` by default and ships without auth —
  put it behind your platform's auth/rate-limiting before exposing it publicly.
- PDF encryption uses the audited `@cantoo/pdf-lib` fork (AES-256, ISO
  32000-2) in-browser; every protected output is verified to refuse opening
  without the password before download, and unlock requires the correct
  password (wrong passwords fail — there is no bypass path in the code).

## Reporting

This is a self-hosted utility; report issues in the repository with the tool
name, browser, and a minimal sample file that reproduces the problem.
